# Engineering Skills

## Purpose

This directory contains **actionable engineering skills** — the practical techniques, patterns, and knowledge a senior engineer applies daily. Each skill document teaches **how** to do something well.

Skills are technology-agnostic. They describe universal engineering practices that apply regardless of language, framework, or platform.

## Directory Structure

```
skills/
├── SKILL.md                    # This file — purpose and overview
├── naming-conventions.md       # How to name things consistently
├── error-handling.md           # Error handling strategies and patterns
├── testing-strategy.md         # Testing approaches and techniques
├── code-organization.md        # File, module, and project structure
├── dependency-management.md    # Managing internal and external dependencies
├── api-design.md               # Designing clean interfaces and contracts
├── data-modeling.md            # Structuring data and state
└── documentation.md            # Writing useful documentation and comments
```

## How to Use These Skills

1. **Before writing code**, review the relevant skill document for the task at hand.
2. **During code review**, reference these skills as objective criteria.
3. **When mentoring**, use these as teaching materials with concrete examples.
4. **When in doubt**, follow the decision rules in each document.

## Relationship to Other Directories

| Directory    | Contains              | Answers           |
| ------------ | --------------------- | ----------------- |
| `skills/`    | Techniques & patterns | **How** to do it  |
| `rules/`     | Principles & standards| **What** to enforce|
| `workflows/` | Processes & sequences | **When** to do it |

## Quality Standard

Every skill document includes:
- Clear explanation of the skill
- Concrete examples (good and bad)
- Anti-patterns to avoid
- Decision rules for ambiguous situations
- Quality checklist for self-review
- Common mistakes with corrections
- Acceptance criteria for "done right"
